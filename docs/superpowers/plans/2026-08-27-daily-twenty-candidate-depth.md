> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox ('- [ ]') syntax for tracking.

**Goal:** Make scheduled and explicitly requested paper updates search deeply enough to add up to 20 unseen autonomous-driving papers while preserving the existing strict relevance filter and 20-paper write cap.

**Architecture:** Keep the crawler and seven-topic relevance pipeline unchanged. Configure production update runs to read 80 results per topic, while overriding push-triggered read-only previews back to 20 so code pushes remain fast. Prove the boundary with workflow regression tests, a live read-only arXiv preview, and an authenticated GitHub Actions update.

**Tech Stack:** GitHub Actions YAML, Python 3.11, unittest, arxiv.py, DeepSeek official API, GitHub Pages.

## Global Constraints

- Formal scheduled and manual update depth is exactly 80 candidates per topic.
- Push-triggered read-only preview depth is exactly 20 candidates per topic.
- Each update writes at most 20 papers.
- Existing topic queries, category allowlist, local relevance filter, canonical ID deduplication, and history deduplication remain unchanged.
- DeepSeek remains 'deepseek-v4-flash' with at most five concurrent workers.
- No API key or GitHub credential is printed or committed.
