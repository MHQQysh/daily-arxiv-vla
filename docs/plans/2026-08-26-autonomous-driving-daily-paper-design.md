# 每日自动驾驶论文站改造设计

## 目标

将 `Infinity4B/daily-arxiv-vla` 改造成每日自动驾驶论文站。保留现有网站的页面结构、视觉风格、论文卡片、搜索、详情页、首图抓取、中文摘要和 GitHub Pages 自动部署能力，将内容范围从 VLA / World Action Model 全量替换为自动驾驶。

目标内容参考 [Awesome Autonomous Driving (2026 Refresh)](https://github.com/autonomousdrivingkr/Awesome-Autonomous-Driving)，覆盖感知、定位与建图、运动与行为预测、规划与决策、控制、端到端驾驶，以及自动驾驶基础模型与世界模型。

## 非目标

- 不把网站改造成 Awesome List 或静态资源导航站。
- 不新增分类页、分类标签或改变当前统一论文流的浏览方式。
- 不重新设计截图中的整体布局、配色和交互。
- 不保留原有 VLA / WAM 论文数据或图片缓存。

## 系统架构

项目继续采用现有链路：

1. Python 爬虫从 arXiv 获取论文。
2. `papers.md` 作为四列表格数据源，字段保持日期、标题、链接、简要总结。
3. DeepSeek 官方 OpenAI 兼容接口根据论文 HTML 生成中文摘要。
4. 图片脚本提取论文首图，并在必要时使用 Playwright 截图兜底。
5. `build_site.py` 生成静态首页、数据文件和论文详情页。
6. GitHub Actions 在代码提交和每日定时任务中更新数据并部署 GitHub Pages。

前端数据协议保持不变，主要改造集中在主题配置、爬虫聚合、摘要提示词、品牌文案和初始数据清理。

## 分方向检索

后台维护七组检索主题：

1. 综合自动驾驶
2. 感知
3. 定位与建图
4. 运动与行为预测
5. 规划与决策
6. 控制
7. 端到端驾驶、基础模型与世界模型

每组检索式由“自动驾驶语境词”和“专业任务词”共同构成。语境词包括 `autonomous driving`、`self-driving`、`automated driving`、`autonomous vehicle`、`driving scene`、`road vehicle` 等；任务词覆盖 BEV、三维检测、车道、占用、多传感器融合、SLAM、高精地图、轨迹预测、行为预测、运动规划、决策、车辆控制、端到端驾驶、VLM 和世界模型等。

允许的 arXiv 主类别扩展为自动驾驶常见类别，包括 `cs.CV`、`cs.RO`、`cs.AI`、`cs.LG`、`cs.MM`、`eess.SY` 和 `eess.IV`。每组结果在进入数据文件前执行相关性过滤。

默认首次每个方向请求约 80 条结果，每日每个方向请求约 10 条最新结果。所有结果按规范化 arXiv ID 去重，忽略 `v1`、`v2` 等版本差异，再按发布日期倒序写入。环境变量可以覆盖默认请求数量和自定义查询。

## 数据清理与兼容性

- 将 `papers.md` 重置为只有表头的空表。
- 删除已有 VLA / WAM 生成站点数据、论文详情页和论文图片缓存。
- 保持四列表格格式，使摘要、图片和站点构建脚本继续兼容。
- 重新运行自动驾驶爬虫后生成新的静态站点。
- 同一论文命中多个主题时只保留一份。

## 中文摘要

摘要仍采用折叠展示，但系统提示词调整为自动驾驶论文阅读模板，重点提取：

- 研究单位与任务定义
- 自动驾驶模块和应用场景
- 输入传感器、表示方法和模型结构
- 使用的数据集、仿真器与训练资源
- 评估基准、指标和关键实验结果
- 实车、闭环或部署条件（若论文提供）

摘要生成失败时保留“待生成”，后续每日任务继续补齐，不阻塞新论文收录和静态站构建。

### DeepSeek API 边界

- 请求直接发送到 DeepSeek 官方 OpenAI 兼容地址 `https://api.deepseek.com`。
- 默认且部署时固定使用模型标识 `deepseek-v4-flash`。
- Python 继续使用官方文档支持的 OpenAI 兼容客户端，但流量不经过 OpenAI、ModelScope 或其他模型代理。
- 删除 ModelScope 环境变量、多模型列表和跨供应商回退逻辑。
- 本地使用 `DEEPSEEK_API_KEY`，GitHub Actions 使用同名 Secret；可选 `DEEPSEEK_BASE_URL` 和 `DEEPSEEK_MODEL` 默认分别为官方地址和 Flash 模型。
- 未配置 DeepSeek 密钥时跳过摘要生成，保留“待生成”并继续构建和部署。

## 页面与文案

页面保持当前视觉和交互，只替换主题相关内容：

- 品牌改为 `Autonomous Driving Research Brief`。
- 主标题改为“自动驾驶每日论文卡”。
- 副标题强调感知、定位、预测、规划、控制与端到端驾驶。
- 搜索示例改为 `UniAD`、`BEVFormer`、`nuScenes`、`motion planning` 等自动驾驶术语。
- 页面标题、SEO 描述、页脚、无结果提示和论文详情页文案统一去除 VLA / WAM 限定。

## 错误处理

- 单一主题查询失败时记录主题名称和错误，继续执行其他主题。
- 所有主题均失败时返回非零状态，防止将空更新当成成功。
- 单篇摘要或图片失败不阻塞其他论文。
- arXiv 请求沿用分页、间隔、重试和指数退避策略。
- 聚合阶段先完成内存去重，确认有有效结果后再更新 `papers.md`。

## 测试与验收

1. 单元测试覆盖主题配置、跨主题去重、版本号归一化、日期排序和部分主题失败。
2. 使用小请求量执行实时 arXiv 冒烟测试，检查结果与自动驾驶相关。
3. 构建完整静态站，确认首页、搜索数据和论文详情页生成成功。
4. 使用浏览器检查桌面端页面与原站布局一致，并检查移动端基本响应式表现。
5. 全仓库扫描残留的 VLA / WAM 品牌文案，允许仅在必要的历史说明或自动驾驶 VLA 论文正文中出现。
6. 确认 `.env` 和真实访问令牌未进入 Git。
7. 推送到用户 fork，确认 GitHub Actions 和 GitHub Pages 配置可运行。

## 部署与密钥边界

仓库内只保留 `.env.example`。DeepSeek 访问令牌通过 GitHub Actions Secret `DEEPSEEK_API_KEY` 注入，不在本地提交、日志或共享配置中持久化。推送前将上游仓库保留为 `upstream`，将用户 fork 设置为 `origin`。若本机没有可用 GitHub 身份验证，代码和本地验证照常完成，最终仅暂停在需要用户授权的推送步骤。
