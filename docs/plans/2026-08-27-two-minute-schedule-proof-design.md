# 两分钟自动定时触发验证设计

## 目标

临时把 GitHub Actions 的每日 cron 改为提交完成后约两分钟的 UTC 时刻，观察一次由 GitHub 自身产生的 'schedule' 事件，并验证完整的论文新增、DeepSeek 摘要、图片、网站构建和 Pages 部署。验证完成后恢复正式的北京时间每天 12:17。

## 方案

- 只修改现有工作流中的 cron，不增加外部调度器，也不使用手动 dispatch 伪装自动触发。
- 临时时间在即将提交时按当前 UTC 计算，设置为约两分钟后的小时和分钟。
- cron 修改提交产生的 push 干跑会被取消，避免 concurrency 队列挡住定时任务。
- 以 GitHub Actions API 中出现 'event=schedule' 的新运行作为触发成功证据。
- 定时运行执行真实新增链路，预计论文总数由 144 增至 164；最终仍受每次最多20篇的硬上限约束。
- 定时运行完成后，将 cron 恢复为 '17 4 * * *'，即北京时间每天12:17，并取消恢复提交产生的冗余 push 干跑。

## 验收

1. 新运行的事件类型必须为 'schedule'，不能用 'workflow_dispatch' 替代。
2. build 和 deploy 两个 job 全部成功。
3. 论文数量恰好增加20；新增论文没有“待生成”，详情页、全图和缩略图齐全。
4. 公网数据文件反映新总数。
5. 仓库最终 cron 恢复为 '17 4 * * *'，工作流仍为 active，本地与远端同步且工作区干净。
