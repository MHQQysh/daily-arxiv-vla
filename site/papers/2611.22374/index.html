Card 03 核心贡献

核心贡献

  • 提出并开源 AutoE2E v1.0，包含模型权重、训练与评估代码，以及可视化检查工具 DataModelConsole。
  • 设计将冻结的 BEVFormer V2 T8 时序相机 BEV 基线与独立的 HD 地图/路线导航编码器通过门控残差与可变形交叉注意力融合的架构。
  • 模型规模约 79.9 M 参数，其中仅约 1.45 M 可训练；在单张消费级 GPU 上可达最高 76 FPS。
  • 在 KITScenes 验证集（Camera + HD Map + Route）上报告开环 ADE/FDE，并与多个 E2E/VLA 驾驶模型在同一 202 关键帧人群上进行跨模型比较。
  • 明确区分相机+地图+路线主评估与仅相机次评估，并报告在 TUM EDGAR 平台上的初步实车研究。
Card 04 方法描述

方法描述

  • 所属模块：作为工作组三波段架构中的“反应波段”（reactive band），以 10 Hz 运行；其余推理波段与世界-动作波段为计划接口，未实现或未训练，且论文结果不依赖它们。
  • 输入传感器：六路相机图像（当前帧加 7 帧历史，间隔 0.5 s，每帧 512×512），当前帧额外 1024×1024 前视相机图像；自车中心 HD 地图栅格（14 通道）与选定路线栅格（2 通道），分辨率 450×300、0.4 m/px；10 Hz 下 6.4 s 自车运动历史（速度、加速度、横摆角速度、曲率，共 256 维）。
  • 场景表示：时序相机 BEV。使用冻结的 BEVFormer V2 R50 T8 官方检查点；ResNet-50 + FPN 形成四层 256 通道特征金字塔；六层 BEVFormer 编码器更新 300×200、256 维的 BEV 查询，BEV 网格覆盖 X ∈ [−60, 120] m、Y ∈ [−60, 60] m，单元 0.6 m；投影算子实现针孔与鱼眼（F-theta）模型。8 帧 BEV 拼接为 2048 通道，经三层 ResNet 风格融合模块（512 中间通道）投影为 256 通道得到 B_img。前视高分辨率分支通过零初始化门控以 tanh(g)⊙δ 残差加入当前帧 BEV。
  • 模型结构：地图编码器 E_map 为全卷积网络（5×5 卷积 stem 96 通道，上下文路径 stride 2/4、192 通道，1×1 投影对齐至 256 通道）；路线编码器 E_route 为轻量卷积网络（96 隐藏通道）；路线贡献经 256 维逐通道门控 σ(g) 加到地图编码上：B_nav = E_map(M) + σ(g)⊙E_route(R)。导航 BEV 通过可变形交叉注意力（8 头、每查询 8 采样点、256 通道）融合进相机 BEV：B_fused = B_img + F_deform(B_img, B_nav)，输出投影与最终 FFN 线性层零初始化，使训练开始时融合为恒等映射。
  • 控制规划器：确定性 GRU（0.835 M 参数），视觉历史输入 h_vis 在评估检查点中置零；在 64 个未来步每步对融合 BEV 做 16 点可变形注意力，GRU 输出加速度与曲率，再由半隐式独轮车模型积分（Δt = 0.1 s）为 XY 轨迹。路线重建头从门控路线贡献解码 2 通道 logits（450×300），以 BCE 与 soft Dice 均值及目标点热图 focal loss（权重 0.25）监督。轨迹损失为 Smooth-L1（β = 1 m）；轨迹权重 1.0、路线重建权重 1.0、BEV 分割权重 0.0。Bezier 与 flow-matching 规划头存在于代码库但未被评估检查点使用。
  • 关键技术：冻结预训练相机 BEV 通路、仅训练导航与规划相关参数；零初始化门控与零初始化输出投影以稳定地将新导航特征接入冻结视觉表征；可变形交叉注意力将稠密 N×N 交叉注意力降为 O(NK)。路线在 KITScenes 中是对整段场景自车轨迹拟合 Lanelet2 地图得到的车道序列，属于事后确定的驾驶意图，目的地为场景结束时的自车位置。
Card 05 数据集与资源

数据集与资源

  • 数据集：nuPlan（用于初始轨迹与路线训练，相机 BEV 主干冻结在官方预训练权重）；KITScenes（用于微调至 Karlsruhe 路网与相机配置，并作为主要外部评估集）。KITScenes 微调使用官方训练划分中排除 129 个空场景后的 404 个可用场景、42,667 个样本；按场景 90%/10% 划分为 364 场景/38,847 样本训练集与 40 场景/3,820 样本内部验证集。评估使用官方 117 场景 Val（11,035 样本）与 206 场景 Test（23,690 样本）。
  • 仿真器：CARLA 因 Vulkan 依赖与 Bottlerocket AMI 不兼容而未被采用；闭环训练路径改为在相同 WebDataset 分片上做离线强化学习（Implicit Q-Learning）；闭环评估通过 NVIDIA AlpaSim 单独推进。原文未报告 AutoE2E 在 AlpaSim 上的通过性验证结果（第 7 节所述首个结果为诊断出的闭环失败模式，提供的节选未包含该节内容）。
  • 模型规模：总计 79,906,522 参数，可训练 1,448,582 参数；冻结相机 BEV 通路占 97.98%（78,292,940 参数）；可训练部分中 GRU 规划器占 57.7%、可变形导航融合占 24.2%、地图/路线编码器加路线门控占 16.9%。
  • 训练资源：AWS EKS Auto Mode Kubernetes 集群；Ray Train 作业经 Kueue GPU 配额调度到 p5en.48xlarge Capacity Block 预留（4 或 8 GPU 作业，整卡分配），保留较小 g6.2xlarge 池用于推理、验证与金丝雀作业。训练使用 8 个分布式 GPU worker、seed 149；基线阶段学习率 1e-4，微调阶段 3e-5，均在 BF16 精度下进行内部验证。原文明确说明具体启动硬件配置（如单台 p5en.48xlarge 8×H200 或 p5.48xlarge 8×H100）为推断而非记录，总训练墙钟时间与 GPU 小时数不可得。实验记录与编排使用 MLflow 与 Flyte。
  • 实车平台：Technical University of Munich 的 EDGAR 平台（初步实车研究）；提供的节选未包含第 5.7 节的具体实车证据内容。
