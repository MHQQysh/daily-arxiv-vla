Bend the Clock: Predicting Ahead to Beat Latency in Event-Based Object Detection

2026-09-22 · 原文 · 翻译 · 2609.26919

论文面向事件相机的多目标检测任务，应用场景包括自动驾驶、敏捷飞行和机器人拦截等高速机器人感知场景。 研究问题源于“观测—可用性不匹配”（observation–availability mismatch）：检测器在时间 t 观测，但预测要到 t+Δ 才可用，传统评估在观测时刻比较预测与标注，忽略了机器人真正收到预测时场景已经变化的问题。 论文指出，尽管事件相机具有低延迟优势，现代事件检测器端到端仍需数十毫秒计算，导致输出时检测框可能已经过时，尤其在高速运动场景中更严重。 核心目标是让事件检测器预测“输出可用时”的目标状态，而非“输入被观测时”的目标状态。

Card 02 论文概述

论文概述

  • 论文面向事件相机的多目标检测任务，应用场景包括自动驾驶、敏捷飞行和机器人拦截等高速机器人感知场景。
  • 研究问题源于“观测—可用性不匹配”（observation–availability mismatch）：检测器在时间 t 观测，但预测要到 t+Δ 才可用，传统评估在观测时刻比较预测与标注，忽略了机器人真正收到预测时场景已经变化的问题。
  • 论文指出，尽管事件相机具有低延迟优势，现代事件检测器端到端仍需数十毫秒计算，导致输出时检测框可能已经过时，尤其在高速运动场景中更严重。
  • 核心目标是让事件检测器预测“输出可用时”的目标状态，而非“输入被观测时”的目标状态。
Card 03 核心贡献

核心贡献

  • 量化了事件基目标检测中的观测—可用性不匹配，说明观测时刻评估会高估机器人实际获得的检测精度。
  • 提出 ChronoFuse，一种因果的可用性时刻检测器，结合未来目标监督和因果跨时间融合，使检测结果对齐预测可用时刻。
  • ChronoFuse 的融合路径轻量，仅增加 0.17M 参数和 0.84 ms 平均端到端延迟。
  • 在 1Mpx 驾驶数据、FRED 无人机数据和 EV-Flying 鸟类/昆虫数据上验证方法，可恢复因延迟损失的大部分精度。
  • 在 FRED 上恢复 90.8% 的延迟导致精度损失；在 EV-Flying 上达到 20.95 sAP，为最强标准事件检测器 2.25 sAP 的 9.3 倍。
Card 04 方法描述

方法描述

  • 所属模块：论文属于事件基多目标检测模块，关注检测器输出时间对齐和流式感知评估。
  • 输入传感器：单目事件相机输入，事件表示为 e_i=(x_i,y_i,τ_i,p_i)，其中 (x_i,y_i) 为像素位置，τ_i 为时间戳，p_i∈{-1,+1} 为极性；原文未报告 RGB 与事件融合作为 ChronoFuse 主输入。
  • 场景表示：在每个处理截止 t_k，仅使用积分窗口内事件构造因果输入 X_k=R({e_i \|t_k−T_win<τ_i≤t_k})，不包含 t_k 之后的事件。
  • 模型结构：使用 RVT 编码器和特征金字塔作为特征提取骨干 G_φ，生成多尺度特征金字塔 F_k={F_k^(ℓ)}；使用 YOLOX 风格检测头 D_ψ 输出原始框回归、objectness 和分类预测 Z_k，Post 操作完成解码、分数过滤和 NMS。
  • 未来目标监督：训练目标从观测时刻标注 Y_q(t_k) 改为预测一个预测时域后的标注 Y_k^+=Y_q(t_k+Δ)，其中 Y_k^+ 为同一序列中时间上最接近 t_k+Δ 的有效标注。
  • 跨时间融合模块：在每个金字塔层级，将缓存的前一时刻特征 H_k^(ℓ) 与当前特征 F_k^(ℓ) 分别通过共享的 1×1 卷积、BN 和 SiLU 投影，分支通道数为 C_ℓ/2；按固定“过去—现在”顺序拼接得到 R_k^(ℓ)，再与当前特征残差相加得到融合特征 F̃_k^(ℓ)=F_k^(ℓ)+R_k^(ℓ)。
  • 因果性设计：H_k^(ℓ) 在序列内取 F_{k−1}^(ℓ)，在序列第一步取 F_k^(ℓ)，避免跨序列泄漏；推理后仅缓存未融合的当前金字塔 F_k^(ℓ)，不递归累加时间残差。
  • 初始化与优化：BN 仿射参数 γ_ℓ=β_ℓ=0 零初始化，使初始融合路径输出为 0，保留预训练检测函数；训练最小化检测损失 L_det(Z_k,Y_k^+)，YOLOX 头使用未来框重新计算 SimOTA 分配。
  • 原文未报告：论文未报告融合模块的具体网络深度、每层特征维度 C_ℓ 的详细数值、训练迭代数、优化器类型和学习率等训练细节。

Card 06 评估与结果

评估与结果

  • 评估基准：1Mpx、FRED、EV-Flying，使用流式平均精度 sAP、sAP50、sAP75；固定流式时域 Δ=33.33 ms，即 30 Hz 的一个时间步。
  • 延迟感知评估：预测由 t 时刻前事件计算，但与 t+Δ 时刻真值比较；评估在 NVIDIA RTX 3090 上完成，时间包含表示构造、推理、预测传输、解码和 NMS。
  • 对比方法：RVT、SAST、S5-ViT、SMamba；以及 RVT+Constant Velocity、RVT+Kalman 外推基线；还比较了 RGB 流式检测器 StreamYOLO 在同步 FRED 序列上的结果。
  • 延迟测量：RVT 平均 29.89 ms、中位 28.81 ms、P90 37.27 ms、P95 41.65 ms；SAST 平均 47.86 ms；S5-ViT 平均 38.38 ms；SMamba 平均 45.17 ms。
  • 1Mpx 结果：33.33 ms 延迟使 RVT 从 47.39 sAP 降至 43.17 sAP；ChronoFuse 达到 46.20 sAP，比 RVT+Constant Velocity 高 1.48，比 RVT+Kalman 高 0.65，恢复 71.8% 延迟损失，距离零延迟参考仅 1.19 点；sAP50 从 73.70 提升到 74.93，sAP75 从 42.84 提升到 47.60。
  • 1Mpx 运动分组：RVT 延迟损失从低运动的 0.53 sAP 增至中运动的 2.23 和高运动的 10.06；高运动 sAP75 损失达 15.44 点；ChronoFuse 在中运动恢复 1.83 sAP，在高运动恢复 7.76 sAP，恢复高运动损失的 77%。
  • FRED 结果：RVT 观测时刻 46.82 sAP，33.33 ms 可用时降至 26.88 sAP，损失 19.94 点；Constant Velocity 和 Kalman 恢复至 39.75 和 39.98 sAP，分别恢复 64.5% 和 65.7%；ChronoFuse 达到 44.99 sAP，比可用时刻 RVT 高 18.11 点，恢复 90.8% 损失，距离观测时刻参考 1.83 点；sAP50 提升 11.39 点，sAP75 从 12.25 提升到 40.93，提升 28.68 点。
