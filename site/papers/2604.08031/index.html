Card 03 核心贡献

核心贡献

  • 提出 POINT 基准测试集：在 nuPlan 混合仿真器上构建了一个包含 1,050 对指令-场景配对的高保真、闭环评估数据集，并包含开放式指令、多种闭环评估指标和竞争性基线方法。
  • 提出以调度为中心的框架：该框架利用 LLM 对开放式指令进行意图推断，生成可执行脚本，调度多个基于 MPC 的运动规划器，并利用异步触发机制实现实时反馈驱动的规划器切换，保持语言到控制的透明决策链。
  • 开展全面的实验评估：与基于 LLM 的、数据驱动的和基于规则的方法进行了多指标对比。结果显示，所提框架在指令实现率上比指令实现基线方法提升 64%-200%，且仅需单次 LLM 查询；安全性和合规性与专用的自动驾驶方法相当。
  • 验证对 LLM 推理延迟的鲁棒性：实验表明，该框架在引入受控延迟的情况下，指令实现率虽有下降但安全指标保持稳定。
Card 04 方法描述

方法描述

  • 所属模块：高层决策与运动规划（LLM 驱动的调度器 + MPC 运动规划器 + LQR 控制器），属于模块化自动驾驶架构中的规划决策模块。
  • 输入传感器：原文未明确列出具体传感器类型；框架采用文本场景描述为 LLM 提供环境上下文，而底层规划器使用“3D detections 和 HD maps”进行轨迹规划。
  • 场景表示：高层 LLM 接收“textual scene description”进行意图推断；底层调度-规划-控制闭环直接作用于“structured perception signals”（如道路几何、动态目标状态等）。
  • 模型结构：整体框架分为两层。高层：LLM（如 DeepSeek-V3、Qwen-2.5 等开源模型）进行低频率意图推断并生成调度脚本；底层：由 5 个行为特定的 MPC 规划器（车道保持、左变道、右变道、加速、减速）负责高频轨迹规划，再用 LQR 控制器输出连续控制信号。
  • 关键技术：采用任务调度视角将 LLM 驱动的 AD 方法分为三种模式（I：静态参数配置；II：持续决策；III：单次生成调度脚本），本文采用模式 III；引入“coroutine mechanisms”与“asynchronous triggers”（异步定时触发条件）实现基于场景图的规划器切换。

Card 06 评估与结果

评估与结果

  • 评估基准：在 POINT 基准上开展闭环评估，涵盖意图识别（REC）、指令实现（REA）、安全性（防碰撞、TTC）与合规性（可行驶区域、限速、方向一致性）指标，另含效率指标（专家轨迹进度）。
  • 评估指标：任务相关指标包括意图识别（Intent Recognition，正确解析比例）、指令实现率（Instruction Realization，成功执行比例）；安全指标包括防碰撞率（Collision Avoidance）、最小碰撞时间（TTC）；合规指标包括可行驶区域（Drivable Area）、限速得分（Speed Limit Score）、方向一致性（Direction Consistency）。
  • 关键数值：单次 LLM 查询条件下，所提框架在指令实现率达到 0.84，相较 Diffusion-ES（0.28）和 DiLu++（0.51）分别显著提升；消融研究显示，加入交通上下文使 DeepSeek-V3 的意图识别性能提升约 10%（从 0.78 提升至 0.86）；仅使用单一规划器（如车道保持）时指令实现率降至 0.12-0.18。
  • 对比方法：专用 AD 方法（LogReplay、IDM、PDMClosed、DiLu+）与指令实现方法（Diffusion-ES、DiLu++）；所有 LLM 驱动方法使用相同的 DeepSeek-V3 主干网络。
  • 评估条件：闭环仿真；实验在工作室（Intel Xeon Gold 5220 CPU、NVIDIA A40 GPU）上进行。LLM 在默认对话温度下运行；延迟敏感性分析在 LLM 决策过程中注入受控延迟进行测试。
