Card 02 论文概述

论文概述

  • 论文面向端到端自动驾驶中的视觉编码器设计，任务是从多相机、多帧图像及自车状态与导航输入预测未来自车轨迹。

Card 03 核心贡献

核心贡献

  • 提出 ConDenseDrive 三阶段框架，使视觉编码器成为“知识稠密、token 稀疏”的编码器，用于端到端驾驶。
  • 第一阶段通过多教师视觉蒸馏，将视觉、语义、几何三类互补知识蒸馏到紧凑学生编码器，在不增加编码器规模的情况下提升表示质量。
  • 第二阶段进行多帧 register 适配，将时空上下文聚合进 register token 供规划使用。
  • 第三阶段提出 register 引导的 token 压缩，利用面向驾驶的 register token 注意力保留信息量大的 patch token、融合其余 token，无需辅助路由网络。
  • 在 NAVSIM v1 取得 94.5 PDMS、NAVSIM v2 取得 90.8 EPDMS，并在 HUGSIM 零样本闭环评测取得 37.4 HD-Score，同时实现 2.0× 加速。
Card 04 方法描述

方法描述

  • 所属模块：视觉编码模块，论文保持下游规划器接口不变，仅优化视觉编码器。
  • 输入传感器：端到端训练使用前、后、左、右四个相机图像，缩放至 1136×672；辅助输入包括自车状态与导航信息；每视角每帧使用 R=16 个 register token。
  • 场景表示：通过每个相机视角各自的 register token 聚合空间信息，再经时间注意力聚合跨帧信息，register token 连同自车状态与导航信息送入轨迹生成器与评分器。
  • 模型结构：学生编码器为 DeiT-S；第一阶段使用冻结教师 DINOv3 ViT-L/16、SigLIP2-SO400M NaFlex、Depth Anything 3-Large，分别提供视觉、语义、几何监督；采用逐教师卷积适配器对齐空间分辨率与通道宽度，损失为余弦损失与 Smooth L1 损失的等权多教师平均，仅优化学生与适配器，之后丢弃适配器。
  • 第二阶段：将蒸馏编码器放入 DrivoR 的规划架构中进行端到端训练，此阶段保留全部 patch token；空间注意力由相机特定 register token 与 patch token 共同自注意力完成；时间注意力在各相机流内对帧级 register token 序列施加，并加入学习的时间嵌入与由相对平面运动得到的自车运动嵌入；端到端目标为轨迹最小 L1 损失与驾驶质量分数二分类交叉熵损失之和；蒸馏骨干权重冻结并用 LoRA 适配，规划器联合训练。
  • 第三阶段：在选定的 Transformer 块中做 token 压缩；以 R 个 register token 对每个可压缩 token 在 H 个注意力头上的平均注意力作为路由分数；始终保留 register 与 CLS token，保留分数最高的比例 ρ，其余低分 token 按未归一化的路由分数加权求和融合为单个 token，融合 token 继续参与后续块并可在后续压缩中再次被处理；不引入辅助路由网络或损失。

Card 06 评估与结果

评估与结果

  • 评估基准：NAVSIM v1 navtest（PDMS 及 NC、DAC、TTC、Comf.、EP 子指标）、NAVSIM v2 navtest（EPDMS 及 NC、DAC、DDC、TLC、EP、TTC、LK、HC、EC 子指标）、HUGSIM 全部 436 个场景的零样本闭环评测（HD-Score 及 NC、DAC、TTC、COM、PDMS、RC 与 Easy/Medium/Hard/Extreme 分难度分数）。
  • 开环/闭环条件：NAVSIM 为开环评测；HUGSIM 为零样本闭环仿真评测；未报告实车评测。
  • NAVSIM v1 关键结果：T=2、ρ=0.4 时 PDMS 94.5，NC 99.3、DAC 98.8、TTC 96.8、Comf. 100、EP 91.9，比人类驾驶员参考 94.8 低 0.3；优于 DriveSuprim（93.5）、RAP-DINO（93.8）、DrivoR（93.7）、DiffusionDriveV2（91.2）、Hydra-MDP（90.3）、GoalFlow（90.3）等。
  • NAVSIM v2 关键结果：同配置下 EPDMS 90.8（官方修正后评测器）、EPDMS* 87.1（原始评测代码）；NC 99.4、DAC 99.1、DDC 99.7、TLC 99.5、EP 90.3、TTC 98.8、LK 96.1、HC 97.8、EC 71.0；比采用同类 DrivoR 风格规划器的 CLOVER 高 0.4 EPDMS，EP 高 3.4 分，NC 持平。
  • HUGSIM 零样本结果：T=1、ρ=0.7 时 HD-Score 37.4，比 DrivoR 的 32.5 高 4.9 分；中等难度场景 HD-Score 从 29.1 提升到 41.2；NC 79.7、DAC 96.8、TTC 54.1、COM 93.9、PDMS 53.3、RC 49.9，Easy 41.2、Medium 21.8、Hard 13.3。
  • 效率结果：T=2、ρ=0.4 时 94.5 PDMS、26.6 FPS；同 T=2 下 ρ 从 1.0 降至 0.4 带来 2.0× 加速且规划性能提升；T=1、ρ=0.3 时 44.5 FPS、94.0 PDMS，仅比未压缩版本低 0.1；T=1 下 token 压缩在 ρ=0.7 和 ρ=0.3 时分别相对 ρ=1.0 降低感知延迟 30.0% 和 46.6%。
  • 消融：三阶段逐步叠加在 NAVSIM v1 上从 91.8 PDMS（原始预训练 DeiT-S）提升至 94.1（+蒸馏）、94.3（+时间注意力，T=2）、94.5（+压缩，T=2、ρ=0.4，26.6 FPS）；路由 token 使用 register 相比 CLS 在 T=1、ρ=0.7 下 PDMS 从 94.0 提升至 94.3；压缩阶段从完整 Stage 2 检查点初始化优于从 DeiT-S 直接初始化（对应表 6 的数值在所给 HTML 中被截断，原文该表后续内容未完整给出）。
