Card 02 论文概述

论文概述

  • 论文任务：针对推理型端到端自动驾驶系统进行推理延迟分析与优化。
  • 应用场景：推理型视觉-语言-动作（VLA）模型的实时自动驾驶推理，重点在于多轨迹预测场景下的效率提升。
  • 研究问题：论文以 NVIDIA 的 Alpamayo 1 系统（采用多推理架构与扩散式动作生成）为对象，探究如何在不显著牺牲轨迹多样性与预测质量的前提下，降低其推理延迟。
Card 03 核心贡献

核心贡献

  • 给出 Alpamayo 推理架构的模块级剖析，并通过运行时性能分析获得各组件延迟分布。
  • 将 Alpamayo 从多推理架构重构为单推理架构，实验表明单推理相比多推理并未显著降低轨迹多样性与预测准确性。
  • 提出静态 KV 缓存管理方案，消除扩散式动作生成中不必要的内存复制与重分配开销。
  • 在静态 KV 缓存基础上引入 CUDA graph 捕获，去除逐 kernel 启动开销与 GPU 空闲间隙，实现延迟进一步下降。
  • 结合两种优化，在六条轨迹场景下实现最高 69.23% 的端到端推理延迟降低，同时保持轨迹多样性与预测质量。
Card 04 方法描述

方法描述

  • 所属模块：端到端推理系统，包含预处理、推理、动作生成和后处理四个模块。
  • 输入传感器：相机图像（四相机：前视、前视变焦、左视、右视，10 Hz 采样，取最近四帧），文本提示（系统提示与用户提示），以及过去自车轨迹（16 个位姿，覆盖过去 1.6 秒）。
  • 场景表示：相机图像经图像 tokenizer 处理；自车轨迹在文本 token 空间的离散表示；推理结果作为 KV 缓存条件化后续动作生成。
  • 模型结构：Alpamayo 为 VLA 模型，核心为三个基于 Transformer 的 DNN——视觉编码器（27 个 Transformer 块）、语言解码器（36 个 Transformer 块）和动作解码器（36 个 Transformer 块）。
  • 关键技术：论文提供两项优化：其一为单推理架构重构，即一次推理生成单个推理序列，其 KV 缓存被复制并共享用于批量生成多条轨迹；其二为动作生成阶段优化，包含静态 KV 缓存管理（预分配缓冲区、基于索引原地写入、用 KV 指针追踪位置）与 CUDA graph 捕获（在第二次扩散迭代捕获，此后各迭代以图重放方式执行）。

Card 06 评估与结果

评估与结果

  • 评估基准：开环评估于 NVIDIA Physical AI Dataset，闭环仿真评估于 AlpaSim。
  • 评估指标：开环采用 minADE6@6.4s（6 条轨迹中取最小 ADE，预测时域 6.4 秒）；闭环采用论文自定义的 DTF（Distance-to-Failure，自车在首个失效事件前行驶距离，失效为用户定义）——原文未报告封闭数据集中的失效定义细节，但 DTF 为论文自定义。
  • 关键数值：结果表明，单推理实现 minADE6@6.4s 为 0.743，多推理为 0.725；闭环单推理 DTF 为 137.12 m，多推理为 131.58 m。动作生成延迟降低：单轨迹 +Static KV Cache 降低 21.66%，+Graph Capture 共降低 24.65%；每条扩散迭代延迟从 62.83 ms 降至 49.13 ms，进一步降至 47.00 ms（CUDA 图重放平均 44.83 ms）。优化效果：单轨迹动作生成相对降低 27.69%（0.65 s → 0.47 s），六轨迹降至最高 43.06%（2.09 s → 1.19 s）。整体六轨迹延迟由 13.33 s 降至 4.10 s，降幅最高 69.23%。部分关键数值在图中以近似方式报告，文中亦以每迭代数值给出。
  • 对比方法：多推理（baseline）对单推理的对比；基线动作生成架构对添加静态 KV 缓存与 CUDA graph 捕获的对比。
  • 评估条件：包含开环、闭环仿真及延迟 profiling（在 DGX Spark 上对选定场景进行 100 次测量平均值）。
