Card 02 论文概述

论文概述

  • 面向自动驾驶系统（ADS）和智能交通系统（ITS）的虚拟场景测试，解决大规模测试套件难以扩展的问题。

Card 03 核心贡献

核心贡献

  • 提出了一种自动化、分布式场景仿真测试的架构，覆盖从软件构建到测试结果收集的完整链路。
  • 设计了 K8s-ROS 模板工具链，将 ROS 2 应用一致地打包为 Kubernetes 可用的 Helm charts。
  • 引入动态 Helmfile 清单，实现可复现且可按测试运行定制的仿真环境声明式组合。
  • 基于 Argo Workflows 实现了分布式测试工作流，支持场景分批、集群并行执行、工件与资源指标收集。
  • 在真实 ADS 测试应用中演示了框架与异构场景源及下游评估模块的集成。
Card 04 方法描述

方法描述

  • 所属模块：端到端仿真测试框架，覆盖打包、部署、编排、执行、收集全流程。
  • 输入传感器：原文未报告（框架本身不涉及特定传感器输入）。
  • 场景表示：采用 ASAM OpenX 标准，测试用例由 OpenSCENARIO 文件和道路表示（3D 世界或 OpenDRIVE）构成。
  • 模型结构：架构由四个主要构件组成：(i) K8s-ROS 的 Helm chart 打包、(ii) 动态 Helmfile 环境组合、(iii) 基于 OpenSCENARIO 的测试说明、(iv) 基于 Argo Workflows 的分布式执行流水线。
  • 关键技术：Kubernetes（K3s）、Helm、Helmfile、Argo Workflows、docker-ros 工具链、用于轨迹数据记录的 omega-prime 数据格式。
Card 05 数据集与资源

数据集与资源

  • 实验使用 200 个 OpenSCENARIO 测试用例，覆盖不同地图和复杂度。
  • 应用案例中额外使用 81 个从异构来源（包括 karl. 研究车辆的真实记录和 inD 无人机数据集）聚合的场景。
  • 仿真器：CARLA。
  • 平台：三节点 K3s 集群（1 个控制平面/服务器节点，2 个代理节点），每个节点 64 GB RAM 和 24 GB VRAM GPU；应用案例扩展到 5 个 worker 节点。
  • 实车平台：karl. 研究车辆（用于 ADS 软件堆栈的真实运行）。
  • 模型规模、训练资源：原文未报告。
Card 06 评估与结果

评估与结果

  • 评估基准：与顺序基线（s1-b1）对比的多个分布式配置，配置记为 sX-bY（X = 每节点模拟器实例数，Y = 工作流批大小）。
  • 评估指标：端到端工作流时间、每小时吞吐量、CPU/GPU/RAM 平均利用率，以及稳定性症状（如失败的 pod、工作流重试、控制平面响应能力）。
  • 关键数值：s1-b1 耗时 475.0 分钟、吞吐量 25.3 h⁻¹；s3-b9 耗时降至 58.7 分钟（加速超过 8 倍）、吞吐量 204.5 h⁻¹；其余配置（s1-b9、s2-b9、s2-b60、s2-b200）介于两者之间。
  • 对比方法：所有分布式配置对比顺序基线 s1-b1；不同 s 和 b 值之间的内部对比。
  • 实验条件：仿真测试（CARLA），运行在 K3s 集群上；应用案例包含实际 ADS 软件堆栈和真实场景数据库。
  • 其他结果：增加批量大小（s2-b9 → s2-b60）将时间从 95.0 分钟减至 67.7 分钟，但过大批量（s2-b200）控制平面响应能力下降；每节点 3 个模拟器时 GPU 峰值达 100%，实时因子降低。真实应用案例中，81 个场景在约 2385 秒内完成（约 2.0 场景/分钟）。
