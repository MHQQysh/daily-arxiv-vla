VAST: V2X/Dynamic Map-Aware Autonomous Driving Systems Validation Toolchain

2026-09-17 · 原文 · 翻译 · 2609.19681

论文面向 IoT-to-Edge-to-Cloud 连续体中的协同自动驾驶，提出 V2X/Dynamic Map 感知的验证工具链 VAST，用于系统级验证车辆、路侧基础设施传感器、边缘侧 Dynamic Map 服务与车载自动驾驶栈之间的完整信息路径。 应用场景为基于 Autoware/AWSIM 的仿真验证环境，重点包括遮挡交叉路口（盲区交叉口）下信号违规车辆逼近、行人/车辆冲突等边角场景。 研究问题为三个 RQ：RQ1——Lanelet2 兼容的生成流水线能否在 Autoware/AWSIM/Dynamic Map 验证环境中高效产生可复现的边角场景；RQ2——Dynamic Map 可用性如何影响 Autoware 的系统级行为；RQ3——集成验证流水线的吞吐瓶颈是什么。 论文明确不提出新的搜索算法，而是解决工具链互操作问题，包括 Lanelet2 到 Scenic 的映射、基于 ROS 2 的协同仿真、Dynamic Map 对象注入 Autoware 以及 TTC、PET、碰撞、超时与性能指标的采集。

Card 03 核心贡献

核心贡献

  • 提出 Lanelet2 兼容的 V2X/Dynamic Map 感知验证工具链 VAST，基于 ROS 2 集成 Scenic、Scenario Simulator v2、AWSIM、Autoware 和 SIM-LDM；技术新颖性在于 Lanelet2-to-Scenic 映射层、步进锁定的 Scenic/SS2 协同仿真机制，以及用于成对 Autoware 评估的 Dynamic Map 注入路径。
  • 提供 Dynamic Map 可用性的受控评估：成对执行流水线在同一生成场景分布下，分别在具备与不具备 V2X 派生 Dynamic Map 信息时运行，并基于碰撞、超时、TTC、PET 指标进行定量分析。
  • 给出集成验证流水线的吞吐特性刻画：在 1–16 个 NPC 条件下评估 Scenic/SS2/AWSIM/Autoware/SIM-LDM 流水线执行开销，识别出 AWSIM/Autoware 执行与重启开销而非 Scenic 采样是实际吞吐瓶颈。
  • 在遮挡交叉口场景中验证约束采样对边角场景发现效率的提升，并验证 Dynamic Map 可用性对碰撞率与 TTC/PET 分布的影响。
Card 04 方法描述

方法描述

  • 所属模块：面向协同自动驾驶 CPS 的 V2X/Dynamic Map 感知验证工具链，包含场景生成、协同仿真执行与 V2X 使能的定量评估三部分。
  • 输入传感器：实验中使用车载 LiDAR 与相机作为基线感知输入；Dynamic Map 注入的对象信息来自 AWSIM 提供的仿真对象真值（位置与速度），而非真实基础设施传感器。原文明确网络时延、丢包、抖动、过期更新和基础设施传感器不确定性在当前实验中未被建模。
  • 场景表示：使用 Scenic 作为概率化场景描述语言，场景被定义为场景（物理对象与智能体配置）上的概率分布，支持硬约束（require）与软约束（require[p]）两类约束以及时序逻辑规格。
  • 模型结构：

- 场景生成闭环包含三个阶段：场景采样、仿真执行、观测反馈；观测（实体状态、TTC、PET、碰撞状态）返回 Scenic 用于终止条件评估与成功判定。

- 实现 Environment Module 解析 OSM-XML 格式的 Lanelet2 地图，由每个 lanelet 左右边界点序列构造车道多边形，并以符合 Scenic 标准的 PolygonalRegion 对象暴露；生成五类区域：road（全部可行驶区域）、intersection（交叉口内区域）、straight_road（非交叉口道路）、sidewalk、crosswalk，并提供由 lanelet 连通性导出的 roadDirection 向量场。采样时自动执行对象间碰撞检测与道路边界干涉检查，物理不一致场景在仿真执行前被拒绝。

- 协同仿真架构：在 SS2 的场景解释层新增 Scenic 专用解释器，作为新的 ROS 2 生命周期节点与既有 OpenSCENARIO 解释器并行运行；Scenic 运行时与 SS2 之间采用 ZeroMQ REQ-REP 通信，消息用 Protobuf 序列化。Protobuf schema 定义实体生成请求（SpawnEgoRequest、SpawnNPCVehicleRequest、SpawnPedestrianRequest）以及仿真循环核心消息对（UpdateNPCStatesRequest 与 UpdateNPCStatesResponse）。

- 每一步 Scenic 评估各实体行为并发送 FollowLaneAction（沿指定 lanelet 路线跟随）、FollowTrajectoryAction（沿路点序列轨迹跟随）、SetVelocityAction 等动作给 SS2；SS2 执行动作后调用 api_->updateFrame() 推进一个仿真步，并返回所有实体状态。

- 关键技术：api_->updateFrame() 仅在收到 Scenic 的 UpdateNPCStatesRequest 时调用，使 Scenic 成为仿真唯一时间主控，保证 Scenic 行为逻辑与 AWSIM 物理仿真之间的确定性因果顺序（步进锁定机制）。自车控制完全交给 Autoware，Scenic 只指定自车初始位置与目标位置。

- V2X 使能评估流水线：AWSIM 中 NPC 车辆与行人的真值信息（位置、速度）通过 socket 通信与 Apache Kafka 流式传输至 SIM-LDM 的 DSMS；Autoware 内实现的 V2X 接口节点查询 DSMS 获取当前行驶车道与交叉口内的对象信息，并交付至 Autoware 目标识别模块（/perception/object_recognition）；车载 LiDAR 与相机识别结果与 V2X 对象信息在识别模块内融合，融合后的占据栅格提供给路径规划模块。V2X 可用性由接口节点启动标志切换。

  • 原文未报告：具体网络时延模型、传感器噪声建模细节、Autoware 内部规划算法细节，以及 Scenic 采样器参数配置细节。

Card 06 评估与结果

评估与结果

  • 评估基准：以 Lanelet2 格式城市交叉口地图（含盲角建筑）为评估地图，基线场景为自车进入交叉口时在相交进路上放置 NPC 车辆或行人。
  • 评估指标：Time-to-Collision（TTC）、Post-Encroachment Time（PET）、碰撞率、非碰撞率、通过率、超时、边角场景发现率、场景生成时间、仿真墙钟时间、实时比、CPU 利用率、GPU 利用率、GPU 显存占用、RAM 占用。边角场景判定阈值沿用先前研究：PET < 2.0 s、TTC < 3.0 s。TTC 与 PET 分布使用显著性水平 0.05 的 Wilcoxon 秩和检验。
  • 评估条件：全部为仿真条件，未进行开环或实车评估；RQ2 使用同一场景分布与匹配随机种子进行成对（有无 Dynamic Map）执行。
  • RQ1 结果（约束采样 vs 非约束基线，各生成并执行 25 个场景）：

- 边角场景发现率由基线 40.0%（10/25）提升至提出条件 80.0%（20/25）；通过率由 56.0% 降至 20.0%，基线中出现的 1 次超时在提出条件中消失。提出条件下 1 次运行因基础设施错误失败，重跑后恢复 25 次有效运行。

- 提出条件下全部 20 个边角场景均为 PET 阈值违例；基线产生 4 个 PET 阈值违例、4 个 TTC 阈值违例和 2 个近失事件（PET 与 TTC 阈值同时违例）。

- 最小 PET 均值由基线 2.05 s 降至提出条件 1.56 s，中位数由 2.26 s 降至 1.47 s（基线为 19 次可观测 PET 的运行），标准差由 0.73 s 降至 0.42 s。基线有 6 次运行无 PET 测量值，对应 NPC 未充分穿越交叉口。
