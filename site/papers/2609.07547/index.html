Card 03 核心贡献

核心贡献

  • 提出 Seam-Aware Motion Model（SAMM）：在卡尔曼滤波恒速模型中增加接缝感知校正，当水平速度跳变超过阈值时视为跨接缝事件，将更新后的水平速度缠绕到带符号主区间上，保持目标跨左右接缝时的运动连续性。
  • 提出 OmniEuc（Omni-Euclidean）缝感知距离：对归一化后的框中心，取直接欧氏距离与水平平移一个图像宽度后的缠绕距离的最小值，作为跨接缝情况下稳健的关联代价。
  • 提出复合关联代价 $E_{fuse}$：对缝感知 OmniEuc 距离和 GIoU 派生代价进行加权融合（$E_{fuse}=\lambda E_{OmniEuc}+(1-\lambda)E_{GIoU}$），兼顾无重叠与跨缝情形与框良好对齐情形下的互补匹配信号。
  • 构建并公开 OmniSmall 基准：一个专门用于全景影像小目标跟踪的野生动物真实轨迹数据集，包含 9 段序列、2551 帧、199 条轨迹，其中 87.12% 的框属于小目标。
  • 在不引入外观编码器、跟踪阶段保持仅 CPU 运行的前提下，在 OmniSmall 上相对基线大幅提升跟踪性能，并在 JRDB 上保持竞争力。
Card 04 方法描述

方法描述

  • 所属模块：tracking-by-detection（TBD）范式下的数据关联与运动模型模块，对 SORT 和 OCSORT 框架进行重设计。检测器为单独训练的单类 YOLOX（作者称之为 OmniSORT/OmniOCSORT 的检测输入来源）。
  • 输入传感器：全景相机采集的等距柱状投影（equirectangular）图像，水平 360°覆盖，存在左右环绕接缝；作者未报告将图像映射为球面表示的处理流程。
  • 场景表示：直接在等距柱状投影的 2D 图像坐标系上进行跟踪，框以归一化 $[0,1]$ 坐标表示，框中心坐标 $u,v$、尺度 $s$（面积）、宽高比 $r$ 构成卡尔曼状态。
  • 模型结构：卡尔曼滤波（SORT 恒速公式，扩展含宽高比导数 $\dot r$），状态向量 $k_i=[u,v,s,r,\dot u,\dot v,\dot s,\dot r]$；数据关联采用匈牙利算法，关联代价为 OmegaEuc 与 GIoU 的加权融合。
  • 关键技术：缝感知速度校正（SAMM 中当 $\|\dot u_{f+1}-\dot u_f\|/\max(\|\dot u_f\|,\epsilon)>\tau$ 时执行 $\dot u_{f+1}=((\dot u_{f+1}+\tfrac12)\bmod 1)-\tfrac12$，其中 $\tau=10.0,\epsilon=10^{-6}$）；缝感知距离取直接与缠绕距离最小值并乘以 $\frac{\sqrt2}{2}$ 归一化到 $[0,1]$；$E_{GIoU}=\frac12(1-\text{GIoU})$；融合权重 $\lambda$ 按数据集、跟踪器和检测来源在训练集上以 0.1 步长网格搜索优化。
Card 05 数据集与资源

数据集与资源

  • OmniSmall：自建数据集，8 段自然飞行行为录制于 QooCam 8K Enterprise（7680×3840，30 FPS，1551 帧）和 Ricoh THETA X（5760×2880，10 FPS，900 帧），另含 1 段 BBC Earth 纪录片片段（5120×2560，100 帧）作为密集鸟群压力测试；共 2551 帧、9 序列、199 条轨迹、20771 个人工标注框。
  • JRDB：公开全景行人跟踪基准（多相机机器人平台拼接成圆柱全景），54 序列、55554 帧、3292 条轨迹、1256363 帧框。
  • 检测器：分别在各数据集上训练的单类 YOLOX；OmniSmall 上以 2:8 时序帧级划分训练/测试，JRDB 采用公开划分。
  • 训练资源：原文未报告具体 GPU 型号、批大小等训练资源细节；实时性测量仅在单颗 CPU 核（AMD Ryzen 9 3900 12-Core Processor）上进行跟踪阶段 FPS。
  • 实车/实机平台：原文未涉及实车；数据采集设备为固定部署的全景相机，跟踪代码库地址为 https://github.com/Xin-Shu/OmniSORT.git。
Card 06 评估与结果

评估与结果

  • 评估基准：OmniSmall（自建，9 序列）和 JRDB-panorama；消融研究在 OmniSmall 上以 GT 检测进行。
  • 评估条件：开环离线评估，区分 ground-truth（GT）检测与 YOLOX 检测两种输入条件；对比仅限非外观式 TBD 跟踪器。
  • 评估指标：HOTA（主指标）、MOTA、IDF1、IDSw，另报告跟踪阶段 FPS；显著性采用配对逐序列精确符号翻转检验。
  • GT 检测关键结果——OmniSmall：OmniOCSORT（$\lambda=0.7$）相对 OCSORT 提升 +8.51 HOTA、+9.41 MOTA、+10.17 IDF1，IDSw 从 382 降至 62；OmniSORT 相对 SORT（66.98 HOTA）提升 +27.12 HOTA。JRDB：OmniSORT HOTA 从 62.43 升至 67.69，OmniOCSORT HOTA 从 66.24 升至 67.01，均优于对比的 ByteTrack 与 HybridSORT 中大部分指标。
  • YOLOX 检测结果——OmniSmall：OmniOCSORT 取得最佳 HOTA 41.76、MOTA 26.97、IDF1 50.72；OmniSORT HOTA 41.11，增益相对 SORT 收窄至约 +1.95 HOTA。JRDB：ByteTrack 最佳（HOTA 31.92），OmniOCSORT HOTA 27.70 优于 SORT（26.45）与 OCSORT（26.45）。
  • 消融结果（OmniSmall GT 检测）：SAMM 单独使用显著损害性能（SORT 66.98→20.05 HOTA，OCSORT 85.61→23.67 HOTA）；$E_{fuse}$ 两单项端点互补（SORT 单独 OmniEuc 73.75 优于单独 GIoU 60.53；OCSORT 相反 52.23 vs 65.71）；两者均远低于融合权重 $\lambda=0.7$ 时的 94.10/94.12 HOTA；最优配置 $\bar p=0.0039$。
  • 运行速度（跟踪阶段，单 CPU 核，YOLOX 检测）：OmniSORT 320/1122 FPS（JRDB/OmniSmall），OmniOCSORT 260/862 FPS；作者未报告完整检测管线端到端帧率或闭环仿真评测。
