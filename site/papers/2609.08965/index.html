PlannerForge: LLM Agents for Scenario-Based Testing of Motion Planners in Autonomous Driving

2026-09-08 · 原文 · 翻译 · 2609.08965

本文提出 PlannerForge，一个用于自动驾驶运动规划器场景测试的统一 LLM-Agent 框架。 该框架覆盖基于场景测试的全部生命周期，包括场景生成、检索、修改、测试执行和结果分析，并新增两个 LLM 增强阶段：ADS增强（规划器调参）和 ADS基准测试（跨规划器对比）。 旨在解决当前自动驾驶系统验证流程中各阶段工具割裂、依赖人工脚本、缺乏统一交互的问题。

论文概述

  • 本文提出 PlannerForge，一个用于自动驾驶运动规划器场景测试的统一 LLM-Agent 框架。
  • 该框架覆盖基于场景测试的全部生命周期，包括场景生成、检索、修改、测试执行和结果分析，并新增两个 LLM 增强阶段：ADS增强（规划器调参）和 ADS基准测试（跨规划器对比）。

Card 03 核心贡献

核心贡献

  • 提出 PlannerForge，据作者所述是首个将全部场景测试阶段（Scenario Source、Generation、Database、Selection、Test Execution、ADS Assessment，以及 ADS Enhancement 和 ADS Benchmarking）统一到单一聊天机器人驱动流水线中的全生命周期 LLM 框架。
  • 引入 Module Router，作为意图分类器，打破传统线性（生成→选择→修改→测试→分析）流程，支持灵活的任务分发。
  • 对十个现成 LLM 后端（五个商业、五个开源）在五个核心任务和八种任务切片下的六种提示条件进行实证评估，验证无需领域微调即可驱动整个框架。
  • 提供一个统一的多规划器接口，支持对生成和修改场景进行规划器对比评估，封装了 Frenetix 和 MP-RBFN 两个规划器。
  • 该框架支持自然语言驱动的场景生成（基于真实 OSM 地图）与场景修改（通过 SUMO 往返转换），实现真实可执行的测试场景合成。
Card 04 方法描述

方法描述

  • 所属模块：本文方法属于自动驾驶测试领域的场景级测试与验证模块，针对运动规划器。
  • 输入传感器：原文未直接报告传感器输入；框架输入为自然语言用户查询、基于 OpenStreetMap 的真实路网拓扑、以及来自 CommonRoad 数据库的场景 XML 文件。
  • 场景表示：场景以 CommonRoad 格式的 XML 文件表示，并附加结构化元数据（含位置、路边构造、参与者、自车四个场景层）；生成和修改过程涉及 SUMO 的 .net.xml 与 .vehicles.rou.xml 中间表示，以及通过 CommonRoad-SUMO 接口的往返转换生成运动学可行的轨迹。
  • 模型结构：统一 LLM 智能体框架，包含六种 LLM 模块：模块路由器、场景生成模块、场景选择模块、场景修改模块、规划器测试与增强模块、结果分析模块，通过 LangChain 后端与 Gradio 前端构建聊天机器人接口。
  • 关键技术：

- 双阶段函数调用实现模块路由与参数提取；用于选择/搜索的 Chroma 向量数据库架构；采用结构化元数据的交错槽位提取流水线，用于多阶段数据库剪枝。

- LLM 提示技术包括上下文提示、思维链和上下文学习，用于生成符合特定场景与配置规格的输出。

- 修改模块支持四种编辑类型：轨迹变更、行为变更、行驶参与者增删以及规划目标变更，针对 T、B、P、G 类型分别使用专用提示模板。

- 测试模块在单个或批次模式下调用统一规划器接口，结果分析模块根据轨迹、碰撞标志和成本日志生成定量检查摘要与定性分析。

Card 06 评估与结果

评估与结果

  • 评估框架与指标：在生成、选择、修改、模块路由以及规划器测试/增强任务上，使用 N=200、查询量和 10 种模型变体在 6 种提示条件下进行了评估。报告指标包括生成意图解析分数；选择的“所有满足”分数；修改的子任务特定验收标准（例如“结束百分比”、预设百分比、“计数匹配百分比”、“GT 边缘百分比”）；此外还有意图分类和 YAML 编辑匹配的准确率分数，以及回归的端到端成功率和成本。
  • 生成：最佳，模型 Glm-5 + cp_cot 达到 0.957，高于基线时分数（0.783，使用 Baseline 提示）0.174。
  • 选择：最佳，Qwen3.6-plus 和 cp_cot 达到 0.880 的“所有满足”分数，高于基线时 0.180。
  • 修改：最佳性能、与 cp_icl_cot 搭配的 Qwen3.6-plus，在 T、B、P、G 子任务的核心检查上达到约 100%。行为修改无法进行零样本处理（0%），但使用进阶提示后达到 100%；结构性修改的零样本基线较高。
  • 模块路由：最佳性能模型为带 cp_icl_cot 的 Gemma4:31b，得分 0.997；对比指标：手工设定的正则表达式路由器仅取得 45.5%。
  • 规划器测试与增强：最佳性能、与 cp_icl 搭配的 Gpt-5.4-mini，取得 1.000 的完美分数；对比的受约束 YAML 编辑器基线为 72.5%。
  • 端到端评估：使用 N=200 个查询、结合 cp_icl_cot 将 qwen3.6-plus 与 qwen3.6:35b 串联（生成→数据库→选择→修改→测试→增强），商业模型与开源平均每个场景分别保留 83%/78% 的累积成功率，每次约 126 秒/99 秒延迟与 42.5k/32.6k token 使用；各阶段故障出现在选择（6%/11%）和修改（9%/8%）。
  • 对比方法：PlannerForge 在生成方面优于 Scenario Factory 2.0（193 vs. 144个可执行结果/200个输出、属性保留率 92–96% vs. 92–96%）、在排名第 1 的选择精度上优于 BM25（92.0% vs. 67.5%）、在物理上有效的修改上优于 Words-to-Collisions（≥94% vs. 31%）。
  • 调参/增强结果：通过 LLM 驱动的成本调参（批次规模 N=400），规划器成功率从 50.4% 提高到 70.2%，每批次碰撞从 19.0% 降到 8.4%。结果报告回归差分、稳定性以及正确 LLM 调参决定，其中使用非特定规划器或配对的规划器参数映射。
